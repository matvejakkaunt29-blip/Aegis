# Muse Mobile — архитектура (черновик, 2026-11-03)

## Решение пользователя (зафиксировано)
- Отдельный APK, без моста на ПК и без зависимости от ПК пользователя.
- Muse — встроенный провайдер по умолчанию: открыл приложение — Muse уже выбран, ничего вводить не надо.
- Очень модульно: любой плагин, модуль и тема приложения генерируются в чате и ставятся без пересборки APK.
- Дизайн мобилы — отдельный, не копия ПК-версии.

## Важное уточнение про «встроенный»
«Встроенный» здесь = нулевая настройка для пользователя, а не модель внутри телефона.
Muse Spark — большая модель, её веса в APK не положить и офлайн она работать не будет.
Приложение ходит в сервис Muse по интернету, просто эндпоинт и авторизация уже
зашиты в сборку разработчиком, а не вводятся пользователем и не идут через его ПК.

Если позже понадобится офлайн-режим — это отдельный плагин с маленькой on-device
моделью, а не замена Muse.

## Состав
- **app-core (Kotlin + Jetpack Compose, планируется):** навигация, чат, хранилище
  чатов (локально, Room/DataStore), шифрованное хранилище токенов.
- **provider-api:** единый интерфейс для всех провайдеров:
  `chat(stream) / listModels / callTool`. MuseProvider — реализация по умолчанию,
  уже выбранная при первом запуске. Другие провайдеры добавляются пользователем
  вручную (OpenAI-совместимый endpoint + ключ) как опция, а не обязательство.
- **tool-registry:** инструменты только внутри приложения и только с разрешениями,
  которые дал пользователь: файлы в папке приложения, заметки, поиск в сети,
  открытие ссылок, калькулятор. Новый инструмент = плагин, а не пересборка.
- **plugin-loader:** плагин = zip/папка с `plugin.json` (манифест, права, версия,
  точки входа) + UI-описание + инструменты. Установка: проверка манифеста ->
  проверка прав -> предпросмотр -> установка -> откат одной кнопкой.
- **theme-engine:** тема = JSON с токенами (цвета, шрифты, радиусы, формы).
  Применяется через Material 3 без перезапуска. Генерация в чате: модель
  возвращает theme.json -> валидация -> предпросмотр -> «Применить».
- **chat-generation:** в чате можно попросить «сделай тему / добавь модуль X».
  Ответ модели парсится как пакет плагина/темы, а не как обычный текст, и
  предлагается к установке. Никакой код из чата не исполняется без проверки
  манифеста и прав.

## Мобильный UX (отдельно от ПК)
- Нижняя навигация: Чаты / Инструменты / Модули / Настройки.
- Один экран — одна задача, чат на весь экран, переключатель провайдера
  вверху чата (по умолчанию Muse, менять не обязательно).
- Карточки чатов, свайпы, быстрый доступ к установленным плагинам из чата.

## Безопасность
- Ключи/токены — только в EncryptedSharedPreferences / Keystore, никогда
  в обычном тексте и никогда в коде плагина.
- Опасные инструменты — только с подтверждением пользователя в UI.
- Плагин не получает доступ к другим приложениям и данным телефона без
  явного разрешения Android.

## Авторизация — решение от 2026-11-03
Выбрано: вход в Muse-аккаунт внутри приложения, а не relay разработчика.
Первый запуск: экран входа -> системный браузер / WebView на страницу входа
Muse/Meta -> токен сохраняется только в EncryptedSharedPreferences + Keystore,
в чат и плагины токен не передаётся. Выход из аккаунта стирает токен и чаты
остаются локально, но без доступа к Muse до повторного входа. Детали — в AUTH.md.
