# Вход в Muse-аккаунт внутри приложения

## Поток
1. Первый запуск: приложение показывает только экран входа, чат недоступен
   до входа — так провайдер по умолчанию действительно работает сразу после входа,
   без ввода ключей и endpoint'ов.
2. Кнопка «Войти в Muse»: открывается системный браузер (предпочтительно)
   или встроенный WebView на официальную страницу входа Muse/Meta.
   Пароль вводится только на этой странице, приложение его не видит и не хранит.
3. После успешного входа приложение получает токен сессии через redirect
   и сохраняет его только в EncryptedSharedPreferences, ключ шифрования — в Android Keystore.
4. Все запросы к Muse идут с этим токеном в заголовке. Токен никогда не попадает
   в логи, в чат, в плагины и в экспортированные файлы.
5. Истечение сессии: при 401 приложение показывает экран повторного входа,
   локальные чаты при этом не удаляются.
6. Выход: Настройки -> Выйти -> токен удаляется, провайдер Muse становится
   недоступен до следующего входа, другие добавленные вручную провайдеры
   при этом не трогаются.

## Мультиаккаунт (добавлено 2026-11-03)
- В приложении может быть несколько Muse-аккаунтов одновременно.
- Переключение: вверху чата «Аккаунты ▾» — чат нового аккаунта начинается отдельно,
  токены не смешиваются: у каждого аккаунта свой токен в зашифрованном хранилище.
- Добавить аккаунт: «+ Добавить аккаунт» — снова открывается вход Muse.
- Выйти из одного аккаунта: удаляется только его токен, остальные остаются.
- Выйти из всех: удаляются все токены, приложение возвращается на экран входа.

## Что это не решает само по себе
Официального публичного OAuth для сторонних приложений Muse на момент
проектирования нет в открытом доступе как у OpenAI. Поэтому на этапе
реализации каркаса AuthManager делается как отдельный модуль с одним
местом замены: если официальный вход недоступен, меняется только этот
модуль (например, на вход через уже установленное приложение Muse),
а чат, плагины и темы не переписываются.

## Безопасность
- Никаких ключей в коде, в BuildConfig и в plugin.json.
- Токен не передаётся плагинам: плагин вызывает инструменты приложения,
  а не API Muse напрямую.
- Скриншоты экрана входа и автозаполнение паролей — по системным правилам,
  приложение их не обходит.
